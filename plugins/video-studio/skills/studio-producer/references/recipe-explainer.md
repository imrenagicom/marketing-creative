# Recipe: explainer

An explainer teaches one idea or one workflow clearly enough that the viewer can repeat it or wants the product. Narration carries the argument; motion graphics make each claim visible at the moment it is spoken.

## Defaults

| Setting | Default | Notes |
| --- | --- | --- |
| Length | 30–60 s social, 60–120 s landing page | Fewer, clearer beats beat more beats |
| Canvases | 9:16 first, 16:9 second | Each composed independently, never cropped from the other |
| Structure | hook → promise → numbered steps or reasons → payoff → CTA | See the scriptwriter's structures |
| Voice | one narrator, conversational | A presenter character is optional |
| Visuals | graphic shots: title, kinetic keywords, steps, UI card, stat, image, end card | Camera footage arrives with later recipes |
| Take size | 1 shot per take | Voice timing comes first |
| Cut rhythm | change something visible every 2–5 s | A new keyword, card or layout counts |
| Captions | kinetic keywords on screen plus a captions sidecar | Burned-in full captions are optional per platform |
| Music | optional low bed; narration intelligibility wins | Sound design is a later skill; keep music decisions explicit |

## What makes an explainer work

- The hook names the viewer's problem or the payoff within the first 2 seconds.
- Each beat makes one point; its keyword appears on screen as it is spoken.
- Show, don't decorate: a callout points at what the narration names; a simplified UI card replaces an unreadable screen capture.
- The CTA matches the value delivered ("save this" for reference content, "try it" for a product).

## Out of scope for this recipe (v1)

AI-generated live-action footage, lip-synced presenters and continuity references belong to later recipes and skills. Do not substitute paid video generation for a missing graphic.
