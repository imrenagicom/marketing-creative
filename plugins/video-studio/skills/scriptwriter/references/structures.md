# Script structures for explainers

Pick the structure the direction lock names; these notes are about wording it.

## Problem → promise → steps → payoff → CTA

The default explainer. Retention comes from a specific promise and visible delivery of each part.

1. **Hook** (≤ 3 s): the problem as the viewer experiences it, or the result.
2. **Promise** (≤ 3 s): a countable payoff — "three steps", "one setting".
3. **Steps**: each starts with its signpost ("One:", "Pertama,") so the viewer can track progress; one action per step, phrased as something the viewer does.
4. **Payoff**: what changes once they do it; the strongest line goes here, not in the middle.
5. **CTA**: one action that matches the content — *save* for reference value, *follow* for a series, *try* for a product.

## Myth → truth → how

Open with the belief, contradict it in one line, then show the better way. Keep the contradiction concrete ("More features won't fix onboarding — fewer first steps will.").

## Before → after → how

State the bad state and the better state in parallel phrasing, then explain the switch. Works well when the visuals can show both states.

## Question → reveal

Ask the question the viewer has, hold the answer one beat, then reveal. The hold is a real pause in delivery; mark it in `delivery`.

## Timing reminders

- Spoken length, not word count, is what matters; numbers and English terms in Indonesian take longer to say than they look.
- Leave breathing room before the payoff and after the CTA; the composition needs a moment to land the end card.
- A 30-second explainer usually has 6–9 short lines. If you have 15, the video is about two things.
